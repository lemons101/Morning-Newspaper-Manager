# 信息源与通道策略

## 当前目标

为晨报系统提供足够稳定、可解释、可追踪的信息输入，而不是盲目扩大抓取范围。

来源策略服务的不是“爬得多”，而是：

- 让 Top10 候选池有可用素材
- 让 editorial-ready 中间层有足够正文支撑
- 让最终晨报能保持较高的信息密度和可读性

---

## 通道划分

当前信息输入主要分成三类：

### 1. 固定平台来源
这是确定性来源，由配置文件显式维护。

典型来源包括：

- GitHub 高星项目
- GitHub Security Advisories
- Hacker News 热门故事
- SEC RSS
- Federal Reserve RSS
- 邮件告警

特点：

- 来源稳定
- 易追踪
- 上限可控
- 适合作为晨报底盘来源

### 2. Tavily / OpenClaw 搜索来源
这是探索性来源，用来补足固定平台之外的 AI 技术、开源和商业信号。

当前架构不是 Python 直接调用 Tavily，而是文件协作：

```text
Collector 生成 tavily_search_plan.json
OpenClaw 调用 Tavily / web-search 能力
回填 tavily_search_results.json
Collector 合并回主流程
```

特点：

- 更灵活
- 适合补趋势和主题
- 依赖外部协作回填
- 不宜作为唯一主来源

### 3. 邮件告警来源
这是内部告警通道，不与普通资讯混排。

它主要负责：

- 紧急提醒
- 会议 / 截止 / 审批等未来事项
- 与个人或组织相关的内部信号

特点：

- 优先级可能很高
- 不应占用普通 Top10 名额
- 更适合单独展示

---

## 选源原则

### 原则 1：优先来源清晰、可追踪
优先使用：

- 官方 API
- RSS
- 授权搜索服务
- 明确配置来源

### 原则 2：保证来源多样，但不要让单一来源淹没版面
每类来源都应有数量上限，避免单一平台占满候选池。

### 原则 3：来源策略要服务晨报成品，而不是只服务采集
选源的最终目的，不是多抓 JSON，而是提升：

- Top10 候选质量
- 正文抓取成功率
- editorial-ready 素材质量
- 最终页面可读性

### 原则 4：保留来源字段，方便页面和排查
每条记录最好都保留：

- 来源名
- 来源类型
- URL
- 发布时间
- 查询主题 / 来源通道

## 当前来源结构的现实判断

### 已经比较稳的来源
- GitHub 安全公告
- GitHub 高星项目
- Hacker News
- RSS 类来源

### 更依赖外层协作的来源
- Tavily 搜索结果回填

### 更像内部提醒通道的来源
- 邮件告警

---

## 当前不建议的方向

- 一上来无限扩来源
- 为了数量牺牲正文质量
- 过度依赖弱正文来源生成“主要内容”
- 用来源扩张掩盖 Top10 / editorial-ready 质量问题

---

## 当前推荐策略

先稳住这条链：

1. 固定平台来源提供底盘
2. Tavily 搜索补趋势与商业信号
3. 邮件告警独立处理
4. 优先提高正文抓取成功率和来源可读性
5. 让 `top10_editorial_ready.json` 吃到更可用的正文素材

---

## 与展示层的关系

来源策略最终要服务展示层。

也就是说，判断一个来源值不值得保留，不只看“能不能抓到”，还要看：

- 是否能进入 Top10
- 是否能抓到足够正文
- 是否能被整理成可读的中文“主要内容”
- 是否适合出现在晨报页面上

如果不能，宁可降权或替换，也不要把弱来源硬塞进成品页。
